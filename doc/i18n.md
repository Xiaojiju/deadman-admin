# 国际化接入

接口文案按请求头 `Accept-Language` 选择语言。未传、为空或无法识别时使用简体中文。管理端、用户端、开放接口使用同一套规则。

## 调用方

在任意请求上增加：

```http
Accept-Language: zh-CN
```

| 请求头 | 语言 | 资源文件后缀 |
|--------|------|----------------|
| `zh-CN`、`zh-Hans`、`zh` | 简体中文（默认） | `messages_zh_CN.properties` |
| `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` | 繁体中文 | `messages_zh_TW.properties` |
| `bo`、`bo-CN` | 藏文 | `messages_bo.properties` |
| `en`、`en-US` | 英文 | `messages_en.properties` |

带权重时按优先级从高到低匹配，例如 `zh-HK,zh;q=0.9,en;q=0.8` 使用繁体中文。

`Result.msg` 会随语言变化。业务码 `code` 不变。成功时简体为 `成功`，英文为 `Success`。

```bash
curl -H "Accept-Language: en" http://localhost:8080/api/auth/login
```

只翻译统一业务码（`ResultCode`）以及 `new BusinessException(ResultCode)`。代码里直接传入的说明字符串保持原文，例如 `new BusinessException(ResultCode.BAD_REQUEST, "自定义说明")`。

## 模块注册文案

每个模块把自己的文案放在：

```text
src/main/resources/i18n/<模块名>/
├── messages.properties          # 默认回退，与简体中文一致
├── messages_zh_CN.properties
├── messages_zh_TW.properties
├── messages_bo.properties
└── messages_en.properties
```

文件编码 UTF-8。启动时扫描 `classpath*:i18n/**/messages*.properties` 自动注册，不必改公共配置。同名键以先注册的模块为准，键名要带模块前缀。

公共业务码已在 `deadman-common` 中提供，键为 `result.<ResultCode 枚举名>`，例如 `result.USER_NOT_FOUND`。

模块自己的文案在抛出前解析：

```java
throw new BusinessException(
        ResultCode.BAD_REQUEST,
        MessageSourceHolder.resolve("pay.order.closed", "支付单已关闭"));
```

带参数时使用 `{0}`、`{1}`：

```properties
common.param.missing=缺少必填参数：{0}
```

```java
MessageSourceHolder.resolve("common.param.missing", "缺少必填参数：" + name, name);
```

校验注解中的 `{文案键}` 走同一套资源包。

资源不在 `i18n/<模块名>/` 时，实现 `MessageBasenameContributor` 并注册为 Spring Bean，返回不含语言后缀和 `.properties` 的 basename，例如 `i18n/deadman-pay/messages`。
